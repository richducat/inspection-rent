# inspection.rent

The public website for **Inspector Gadgets**, home-inspection software for Florida
inspectors, and the host for its web app at `/app`. Live at https://inspection.rent.

## If you are new here, read in this order

1. [`AGENTS.md`](AGENTS.md) — the working rules and the one-page map. Every engineer and
   every AI assistant (Claude, Codex, anything else) starts here.
2. [`docs/STATUS.md`](docs/STATUS.md) — where things stand today, what is open, and what
   the owner has to do next.
3. [`docs/SYSTEM-MAP.md`](docs/SYSTEM-MAP.md) — every repository, service, domain, and
   account the product depends on, and what breaks when each is down.
4. [`docs/RUNBOOK.md`](docs/RUNBOOK.md) — step-by-step instructions for the recurring jobs:
   change a page, add a page, deploy, roll back, verify.
5. [`docs/ANALYTICS.md`](docs/ANALYTICS.md) — the Google Tag Manager and GA4 setup and
   every event the site and app send.
6. [`docs/DECISIONS.md`](docs/DECISIONS.md) — why things are the way they are, dated, with
   the commit or pull request that decided it.
7. [`docs/CAMPAIGNS.md`](docs/CAMPAIGNS.md) — the ten campaign landing pages and their
   tracking values.

Open work is tracked as GitHub issues in this repository; `docs/STATUS.md` links them.
The other repositories have briefs of their own: the app repo has `CLAUDE.md` (and an
`AGENTS.md` pointer in its PR #6), `hip-records-api` has `CLAUDE.md` and `RUNBOOK.md`,
`hip-accounts-api` has `README.md`, `DEPLOY.md`, `RESTORE.md`, `STRIPE-SETUP.md` (stale prices)
and `docs/MIGRATION.md`.
The system map says which of those to trust, because several are out of date.

## If you are the owner

You never need to run a command. When an engineer or an assistant says "please merge",
open the pull request link, scroll to the bottom, press the green **Merge pull request**,
then **Confirm merge**. About 30 seconds later the website is updated, and the
[Actions tab](https://github.com/richducat/inspection-rent/actions) shows a green check
next to "Deploy to GitHub Pages". Red there means the site did not update; `docs/RUNBOOK.md`
section 1 says what to press. The list of everything open is the
[Issues tab](https://github.com/richducat/inspection-rent/issues); `docs/STATUS.md` starts
with this week's steps for you.

Six words you will meet: a **pull request (PR)** is a proposed change waiting for your
merge; **main** is the copy of the site that is live; a **deploy** is the automatic
publishing after a merge; **GitHub Pages** is the free hosting; the **Actions tab** shows
each deploy's result; **GTM / GA4** are Google's visitor-counting tools.

## For engineers only: quick commands

```bash
npm test               # analytics tracker tests (node 22, no install)
npm run mobilecheck    # every page at 320 px and 375 px; needs playwright (see AGENTS.md)
npm run check          # both
```

## Deploying

- **Marketing pages:** merge a pull request into `main`. GitHub Actions publishes in 20 to
  30 seconds (it can queue for ten minutes on a bad day); watch the "Deploy to GitHub Pages"
  run in the Actions tab. The CDN caches pages for 10 minutes.
- **The app:** built and copied in by `deploy-hip.sh` in `richducat/home-inspection-assistant`,
  run from the owner's Mac. Details and the fallback when that Mac is unavailable are in
  `docs/RUNBOOK.md`.
